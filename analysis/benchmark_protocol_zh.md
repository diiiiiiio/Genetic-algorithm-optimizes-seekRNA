# 相同预算下的计算对照

## 比较问题

在同一起点、评分配置和预算下，比较各方法相对共同起点的累计最高分提升。历史 RS 每次从初始库出发，当前配置每次只走一个编辑事件。能够累计多步的随机方法才是拟议主对照。历史两个方法的当轮平均值口径不同。

## 计数和停止

1. 共同起点按统一评分配置登记一次，单列成本。所有方法从相同的已知起点分数开始。
2. 每个方法、每个种子有独立账本。用相同身份、相同标注和相同评分配置判定重复。相同文本带有冲突标注时记录冲突，单列处理。
3. 预筛淘汰单列。首次把一个候选送入统一的完整评分消耗 1 个预算单位，评分失败同样消耗 1 个。重复请求及缓存命中不再占唯一候选预算。若有重试，另外计实际调用时间与次数。
4. 达到预算即截断记录并冻结该点的累计最高分。并行环境以预先确定的提交顺序占用名额。若方法提前耗尽候选，报告实际预算和原因。在双方都达到的预算点比较，不补值。
5. 最小日志字段包括运行号、方法、种子、请求序号、候选的匿名标识、编辑深度、长度、评分配置、预筛或评分状态、累计已用预算、分数和耗时。报告所有完整评分调用的成功比例以及原始提案数。

## 主要结果与长度检查

每个种子的主要结果为“预算耗尽时累计最高分减去共同起点最高分”。方法差值按种子汇总，报告各次运行值、平均差和对种子配对重抽样的 95% 区间。正式种子清单、预算和主要分析在运行之前锁定。200 条保留记录属于同一运行。

旧表的描述性比较先使用全部原始行。对两种方法共同出现的每个长度，计算两者的平均得分差，再按两方法在该长度中较小的行数加权。这个权重给两组相同的长度构成，不构造候选之间的一对一配对。另报两种敏感性结果：只用两边均至少 5 行的长度，以及剔除旧表中字段不一致的记录后重算。后者用已保存的 GC 字段识别先前发现的不一致，若仍有同序列重复则整组移出敏感性样本。报告始终保留原始结果。阶段性数据缺少全部受评候选、失败及编辑深度时，只作入选样本内的描述。

## 本次核验的入口

在项目根目录使用项目的 Python 运行以下命令。坐标测试直接对当前代码提出预期，发生偏差时返回失败。统计脚本只读已保存的三个 CSV。账本示例使用虚构的整数编号和固定的虚构分数。

```sh
.venv/bin/python -B -m unittest discover -s tests -p test_interval_bookkeeping.py
.venv/bin/python -B -m analysis.archived_lengths
.venv/bin/python -B -m analysis.check_budget
```

数字示例用 3 个种子，每个种子有两条独立的请求流，每条流的唯一调用预算是 32。共同起点命中、预筛拒绝、评分失败、重复失败、流提前耗尽和交换流的运行顺序均有检查。它给出计数与重放核验结果；实际方法差、实际运行时长和生物学功能需要各自适用的证据。
